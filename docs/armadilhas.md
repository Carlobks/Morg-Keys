# Armadilhas (problemas encontrados e a regra para os evitar)

> Numeração das secções (§N) mantida do antigo `COMO-FOI-FEITO.md`; mapa em `docs/README.md`.

Ler antes de mudar qualquer coisa. Cada problema novo entra aqui como A<n+1>, com a regra.

> [!WARNING]
> **Regra n.º 1 (sobretudo para agentes de IA): nunca arrancar o GlazeWM, o Zebar nem o `bar_helper.py boot` / `layout-restore` a partir de um terminal do Claude Code ou de outro agente.**
> Tudo o que eles lançarem herda o ambiente desse terminal (`CLAUDECODE`, `CLAUDE_CODE_*`, `ANTHROPIC_BASE_URL`…). As sessões do Claude Code abertas depois pelos atalhos passam a cobrar **pela API** em vez do plano, e o Windows Terminal pode ficar preso. Para confirmar se um terminal está "contaminado": `Get-ChildItem env: | ? Name -match 'CLAUDE|ANTHROPIC'` (tem de vir vazio). Formas seguras de arrancar: tarefa agendada (`Start-ScheduledTask "GlazeWM (arranque)"`), terminar a sessão do Windows, ou reiniciar. Detalhes em A2 e A22 (§8).

## 8. Armadilhas (cada uma custou horas)

| # | Armadilha | Consequência | Regra |
|---|---|---|---|
| A1 | O `glazewm.exe` tem `uiAccess=true` | CreateProcess, Agendador e chave Run falham com `0x800702E4` (a Run falha **em silêncio**) | Lançar só por ShellExecute (`os.startfile`, `explorer`, `Start-Process`). A tarefa chama o `boot`, que faz ShellExecute. |
| A2 | Herança de ambiente | Se o GlazeWM (ou o Zebar, ou o `boot`/`layout-restore`) for arrancado de uma sessão do Claude Code, tudo o que ele lançar herda `CLAUDECODE`, `CLAUDE_CODE_*` e `ANTHROPIC_BASE_URL`: o Claude Code aberto pelos atalhos passa a cobrar **pela API**, e o Windows Terminal pode ficar preso. Fica assim até o GlazeWM ser fechado. | Nunca arrancar estes programas a partir de um terminal do Claude Code ou de um agente. Seguro: tarefa agendada (`Start-ScheduledTask`, que corre com ambiente limpo), terminar a sessão ou reiniciar. `wm-reload-config` e `glazewm command …` são seguros (não lançam processos novos). Verificar um terminal: `Get-ChildItem env: \| ? Name -match 'CLAUDE\|ANTHROPIC'`. |
| A3 | `shell-exec` do GlazeWM | Divide nos espaços. Aspas à volta do **programa** falham (bug #1417). Nomes curtos de apps da Store (`wt`) podem falhar. | Programa sem aspas e sem espaços (`%ProgramFiles%/…` funciona; `%LOCALAPPDATA%/Microsoft/WindowsApps/wt.exe` por caminho completo). Aspas só nos **argumentos** (`pyw.exe -I "C:/…/bar_helper.py" cmd`). |
| A4 | Job object do GlazeWM | Processos lançados pelo GlazeWM morrem com ele. Os `shutdown_commands` morrem antes de terminar. | O que tem de sobreviver (`after-exit`, `awake-hold`, `bat_tray.py`) sai com `CREATE_BREAKAWAY_FROM_JOB` (`_popen_detached`). |
| A5 | `hide_method: cloak` | Ao sair ou rebentar o GlazeWM, janelas de outros workspaces podem ficar invisíveis mas "abertas" | `after-exit` corre `uncloak.ps1`. À mão: `powershell -File uncloak.ps1`. |
| A6 | Pasta do utilizador com espaços | Os atalhos `wt`/`claude-code` (programa sem aspas, A3) partem | O instalador recusa. Para suportar, seria preciso mudar esses comandos. |
| A7 | Zebar só lê pacotes (`zpack.json`) ao arrancar | Um pacote novo dá "No widget pack found" num Zebar já aberto | Depois de mudar `zpack.json`, fechar **todos** os `zebar.exe` e voltar a abrir. |
| A8 | Permissões do Zebar | `shellExec` só corre o `program` exato com argumentos que batam com `argsRegex` (âncoras `^…$`); senão falha em silêncio | Ao mudar caminhos ou acrescentar um comando, atualizar o `argsRegex` no `zpack.json` e reiniciar o Zebar (A7). |
| A9 | Visibilidade das janelas do Zebar | O estado do Tauri não acompanha o Win32: mostrar pelo JS e esconder pelo Win32 dessincroniza | Um só dono: o `bar_helper.py`. As páginas pedem (`guide-hide`, `layer-hide`, `splash-ready`); não mudam a visibilidade. |
| A10 | Junction em PowerShell 5.1 | `Remove-Item -Recurse` numa junction **apaga o conteúdo do destino** | Remover junctions só com `cmd /c rmdir "<junction>"`. |
| A11 | WebView2 a frio | Até 8 s para pintar, com um clarão branco no início | `transparent: true` nos widgets e a cortina nativa com o BMP até a página avisar (`splash-ready`). |
| A12 | `start-widget-preset` | Arranca o Zebar **só** com esse widget e ignora os `startupConfigs` | O `boot` corre a seguir `zebar startup`, que funciona com o Zebar já aberto. |
| A13 | `keep_alive` dos workspaces | Ignorado sem `bind_to_monitor` | Ambos juntos (`bind_to_monitor: 0`). |
| A14 | `toggle_workspace_on_refocus` | Também afeta o `move` (issue #1397) | Por isso o "mover para workspace N" é `move` + `focus` explícitos. |
| A15 | Regras app→workspace | Moviam popups (o login do Google ia parar a outro workspace) | Não usar. O arranque usa `layout.json`. |
| A16 | `Set-Content`/`Out-File` em PowerShell 5.1 | Escrevem com BOM ou ANSI. O Zebar e o Python rejeitam JSON com BOM. | Escrever com `[IO.File]::WriteAllText(p, t, (New-Object Text.UTF8Encoding $false))`. Os `.ps1` com acentos levam BOM (o 5.1 lê sem BOM como ANSI). |
| A17 | `$ErrorActionPreference='Stop'` + programa nativo com stderr | Em PowerShell 5.1, uma linha em stderr vira exceção | `try { & prog … 2>$null } catch {}`. |
| A18 | Atalhos com Ctrl+Alt | Roubam o AltGr (`@ # € [ ]`). O GlazeWM também rejeita atalhos com modificadores a mais carregados. | Só `Alt` e `Alt+Shift`. O `apps-apply` recusa `Ctrl`. |
| A19 | Foco depois de o Zebar abrir | A janela "Tauri App" roubava o foco | O `boot` e o `layout-restore` repõem o foco no contentor que o GlazeWM diz estar focado. |
| A20 | Python | `python.exe` do PATH pode não existir ou ser outro | Sempre `C:\Windows\py.exe`/`pyw.exe -I`: o lançador escolhe a versão instalada, e `-I` ignora o diretório atual e as variáveis `PYTHON*`. |
| A21 | Passagem cortina nativa → animação | Se o BMP da cortina não for exatamente o 1.º quadro do SVG (tamanho, posição, cores), vê-se um salto no arranque | BMP e SVG com a mesma geometria. Tamanho em `ANIMACOES`, centro a `ANIM_CY` = 38% em ambos. O 1.º quadro (`first()`) não pode ter partes animadas (o vapor do café só começa depois). |
| A22 | Testar o arranque | Chamar o `boot` a partir de um terminal de agente herda o ambiente (A2) | Para ver só a animação: `bar_helper.py animacao preview` (não arranca o GlazeWM nem apps; mas, se o Zebar estiver **fechado**, arranca-o com o ambiente herdado — só correr com o Zebar já aberto). O arranque completo só se testa terminando a sessão ou reiniciando. |
| A23 | Zebar só serve ficheiros do próprio pack | Uma página não consegue importar `../outro-pack/…`; uma junction/symlink também não serve (o caminho é resolvido antes da verificação). Ficheiro fora do `includeFiles` → 404 em silêncio. | Tudo num só pack (`omarchy-catppuccin`). Ficheiro novo que uma página precise de ler: acrescentar o padrão ao `includeFiles` de um dos widgets (o Zebar junta os de todos) e reiniciar o Zebar (A7). Os títulos das janelas dependem do nome do pack (`Zebar - omarchy-catppuccin / <widget>`): mudar o nome do pack obriga a mudar `GUIDE_TITLE`, `BAR_TITLE`, `LAYER_TITLE` e `SPLASH_TITLE` no `bar_helper.py`. |
| A24 | Tarefa agendada criada como administrador | Um utilizador com UAC (token filtrado) não a consegue substituir nem apagar: `Register-ScheduledTask`/`Unregister` dão "Acesso negado" (o desinstalar falhava em silêncio). | O instalador mantém a tarefa antiga se ela já corre o mesmo (`pyw.exe -I "…\bar_helper.py" boot`); senão para e dá o comando para correr como administrador: `schtasks /Delete /TN "GlazeWM (arranque)" /F`. O desinstalar avisa se não a conseguiu tirar. Reinstalar sobre uma fonte JetBrainsMono já instalada (em uso) também não pode falhar: só se copia se for diferente. |
| A25 | Foco do teclado nas páginas do Zebar | `SetFocus` na janela interna `Chrome_RenderWidgetHostHWND` deixa a página sem foco: aparece mas não recebe teclas. Uma janela escondida que continua ativa faz a abertura seguinte não gerar `WM_SETFOCUS`. O JS `tauriWindow.setFocus()` está bloqueado pelas permissões do Zebar 3.3.1. | `_focus_webview`: `SetFocus` na janela de topo + `PostMessage(WM_SETFOCUS)`; o wry responde com `ICoreWebView2Controller.MoveFocus`. Ao esconder, devolver o primeiro plano à janela de antes (`_panel_release`, `_restore_previous`). |
| A26 | Ícones em `<canvas>` no WebView2 | Às vezes saem vazios ou estragados (ex.: Energia e Reiniciar no `Alt+Esc`), sem padrão; no Chromium normal não acontece. | Desenhar em SVG (`<text>` com a mesma centragem medida por `measureText`). Os ícones redesenham-se a cada abertura. |
| A27 | Substituições em massa por script (PowerShell) | Num array `@('a', 'b' + "`n" + 'c')` a vírgula liga antes do `+`: os pares de "procura/troca" desalinham e uma "procura" passa a ser a quebra de linha. Em 2026-10-23 isto pôs o Tutorial.html numa só linha e foi publicado. | Pôr cada valor composto entre parênteses, ou fazer as trocas em Python com `assert` de "exatamente 1 ocorrência". O teste `tests/test_ficheiros_texto.py` falha se algum ficheiro ficar sem quebras de linha ou com linhas gigantes. |
| A28 | Escrever ficheiros com strings "…" do PowerShell | A crase é carácter de escape: `` `n`` vira quebra de linha, `` `a``/`` `v``/`` `0`` viram caracteres invisíveis e as outras crases desaparecem. Em 2026-10-23 três ADR perderam todas as crases do Markdown. | Escrever ficheiros com a ferramenta de escrita (ou here-strings de aspas simples `@'…'@`), nunca com `@"…"@` quando o texto tem crases. O teste `tests/test_ficheiros_texto.py` falha com caracteres de controlo. |
| A29 | `npm install` sem `package.json` no repositório | O npm sobe pastas até encontrar um `package.json`: em 2026-10-23 instalou o Biome no `package.json` pessoal do utilizador (`C:/Users/Usuario`, projeto Excalidraw). | Antes de instalar, criar o `package.json` no repositório (ou usar `--prefix <repo>`) e confirmar com `npm root`. Desfeito com `npm uninstall` na pasta do utilizador. |
| A30 | Teste que lança um hook que corre os testes | Com o hook estragado: testes → hook → testes → hook… Em 2026-10-23 encheu a máquina com **650 processos** (parados à mão). O `timeout` do `subprocess.run` só mata o filho direto, não os netos. | Os testes correm com `MORG_A_TESTAR=1` e o hook não volta a correr testes com essa variável. Testar a **decisão** (função pura), não o processo, quando o processo pode correr testes. Testes que lançam hooks têm `timeout`. |
| A31 | Hooks do Claude Code e a pasta do projeto | Numa sessão **mudada de pasta**, `$CLAUDE_PROJECT_DIR` continua a ser a pasta onde começou. Um script de hook em falta faz o Python sair com **2**, que o Claude Code lê como "bloquear": todas as ferramentas desse hook ficam bloqueadas (o agente não consegue corrigir o `settings.json` sozinho). | O comando do hook procura o script em `$CLAUDE_PROJECT_DIR` e, se não existir, na raiz do git (`git rev-parse --show-toplevel`). Para desbloquear: o utilizador renomeia `.claude/settings.json`. |
| A32 | Hook "testes antes do commit" | (1) Corre **antes do comando inteiro**: num "criar ficheiro e depois fazer o commit" no mesmo comando, os testes correm sem o ficheiro novo (em 2026-10-23 um teste falhado entrou assim; o commit, local, foi desfeito). Testa a pasta de trabalho, não só o que está preparado. (2) Reconhece o commit por texto: um comando que só **menciona** o commit (ex.: um texto a gravar) também corre os testes (falso alarme; só custa tempo, ou recusa se os testes estiverem a falhar). | Criar ou alterar ficheiros num comando e fazer o commit noutro. Gravar textos que falem de commits com a ferramenta de edição, não pela shell. |
| A33 | Hook da A2 e código passado pela shell | O hook lê o comando como texto: código Python colado num comando (heredoc) com `[str(ZEBAR), …]` parece "arrancar o Zebar" (`(` seguido de `ZEBAR`) e é recusado (falso alarme, do lado seguro). | Código vai para um ficheiro com a ferramenta Write; a shell só corre `py -I ficheiro.py`. |
| A34 | Testes que trocam uma função guardada numa tabela | `with patch.object(m, "f", falso), patch.dict(m.TABELA, {k: falso for k, v in … if v is m.f})`: a 2.ª expressão só é avaliada **depois** de entrar na 1.ª, quando `m.f` já é o falso — a tabela não muda e o `main` chama a **função real**. Em 2026-10-23 correu o `awake-hold` real (ficou pendurado a manter o PC acordado; terminado à mão, estado confirmado "off"). | Calcular o que a tabela tem **antes** do `with`. E correr testes de comandos **dentro do `SistemaFalso`**: o que escapar bate numa bomba em vez de mexer no PC. Comandos de teste com `timeout`. |
| A38 | Um `.bat` de `arranque.txt` prende `~\.glzr` | O `cmd` do `.bat` corre a partir de `~\.glzr\arranque\` e o registo dele também lá está; um servidor (ex.: `npm run dev`) passa o ficheiro aberto aos filhos (`node`). Se o ícone (`pythonw` do `bat_tray.py`) fechar sem eles, ficam órfãos e o instalador ou o desinstalador não conseguem mudar o nome à pasta ("acesso negado"). Em 2026-10-26 o desinstalador dizia "Configuração movida" mesmo a falhar. | **Não fechar o programa do utilizador sem perguntar.** O instalador e o desinstalador tentam e, se falhar, avisam qual é o `.bat` (com o PID), como o fechar (Gestor de Tarefas > Detalhes > `cmd.exe` > Terminar árvore de processos) e esperam: Enter tenta outra vez, S sai sem estragar nada. |
| A39 | Nomes de animações escritos à mão no instalador | `[ValidateSet('cafe')]` e a migração do `arranque.txt` antigo (que trocava **qualquer** animação diferente de `cafe` por `cafe`): com uma 2.ª animação, uma reinstalação apagava a escolha do utilizador. | O instalador lê a lista do pacote (os `.bmp` em `omarchy-catppuccin\arranque\`, um por animação, receita 5b) e só troca por `cafe` uma animação que não exista. |
